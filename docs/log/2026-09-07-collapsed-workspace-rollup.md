# 2026-09-07 — свёрнутый воркспейс: счётчик сессий + сводный статус

Состояние: код готов, все гейты зелёные (core 2705, hosted 256, lint 0), проверено глазами на
изолированном Debug-инстансе (`AGTERM_STATE_DIR=/tmp/agx-ru`, оставлен запущенным). **Не закоммичено,
не задеплоено** — лежит в рабочем дереве поверх ветки `action-journal-2026-09-07` другой сессии
(файлы не пересекаются: та правит ControlServer/AppActions/AppStore, эта — `Views/Sidebar*` +
`AgentStatus.rollupRank`).

## Проблема
Свёрнутая строка воркспейса выглядела одинаково с пустой: непонятно, есть ли внутри сессии и ждёт
ли там кто-то (скриншот Руслана: `memory`/`modme` закрыты — что внутри, не видно).

## Решение
- `SessionCountView` (`SidebarRowViews.swift`) — приглушённая цифра после имени, без капсулы,
  моноширинные цифры, alpha 0.45 от цвета текста; 0 → ширина 0 (слот возвращается имени).
  Цепочка в ячейке воркспейса: имя | счётчик | «+» (hover) | статус | badge.
- Сводный статус: `Coordinator.collapsedRollup(for:)` берёт индикатор самой «требующей» сессии —
  `AgentStatus.rollupRank`: blocked (3) > completed (2) > active (1) > idle; при равенстве побеждает
  мигающий; color/shape-override первой такой сессии едет вместе с ним. Раскрытый воркспейс —
  как раньше: ни цифры, ни глифа.
- Свёрнутость берётся из `expandedWorkspaceIDs` (то, что реально показано), а не из
  `Workspace.isExpanded` (persist): подавленный reveal открывает строку без записи на диск.
- `RowContent` получил `sessionCount`; `indicator` у воркспейса = roll-up. Поэтому смена статуса /
  добавление сессии внутри свёрнутого воркспейса перерисовывает его строку штатным диффом reconcile.
- `outlineViewItemDidExpand/DidCollapse` → `reloadRollupRow(node)`: перерисовка строки при
  клике по треугольнику, снапшот обновляется, чтобы следующий reconcile не грузил её повторно.

## Тесты
`agtermTests/SidebarCollapsedRollupTests` — раскрыт: count 0, глиф скрыт; свёрнут: count 2, глиф
`blocked`; смена статуса внутри → `active`; раскрыл обратно → чисто.
